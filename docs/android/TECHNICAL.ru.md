# Что сделано для Android, как и зачем

[English version](TECHNICAL.md)

MarathonRecomp во время сборки превращает исполняемый файл и шейдеры Xbox 360 в код C++ и шейдеры и запускает их через свои слои ядра, звука и графики. Порт сохраняет эту схему и добавляет то, что нужно Android. Основа: MarathonRecomp `a66d4fb` («Rewritten HID backend»).

## 1. Сборка

| Что | Как | Зачем |
|---|---|---|
| Разделение хост/устройство | `MARATHON_RECOMP_HOST_TOOLS_ONLY` собирает XenonRecomp, XenosRecomp, file_to_c и u8extract для Windows; сборка NDK получает их через `MARATHON_RECOMP_HOST_*` (корневой `CMakeLists.txt`, `MarathonRecompLib/CMakeLists.txt`). | Генераторы кода работают на компьютере сборки, всё остальное компилируется под arm64. |
| Без Visual Studio IDE | Триплеты vcpkg в `android/vcpkg-triplets`: `arm64-android-29-release` для устройства и `x64-windows-llvm-host` (clang-cl + lld-link через chainload) для host-портов. | Хватает заголовков MSVC Build Tools. |
| FFmpeg с XMAFRAMES | vcpkg `7087dcfb` + официальный патч `ffmpeg-core`, статические библиотеки (`Build-FFmpeg-Android.ps1`). | Музыка и голоса игры — потоки XMA. |
| SDL3 | Статически в `libmain.so`; Java-часть берётся без изменений из submodule `thirdparty/SDL`. | Окно, ввод, звук и жизненный цикл приложения. |
| Загрузка драйверов Vulkan | `thirdparty/libadrenotools` (BSD-2) и `thirdparty/miniz` для пакетов драйверов. | Позволяет использовать Mesa Turnip вместо драйвера производителя. |
| Переключатели XenonRecomp | `Marathon.toml.in` берёт 8 флагов оптимизации из CMake-опций `MARATHON_RECOMP_PPC_*` (по умолчанию OFF; скрипты Android включают группу 1). | В оригинале они выключены; группа 1 проверена на устройстве (раздел 5). |

## 2. Слой приложения (`MarathonRecomp/os/android/`)

- **`storage_android`** — корень игры запрашивается у лаунчера через JNI (`MarathonActivity.getGameStoragePath()`), по умолчанию `Android/data/<пакет>/files/MarathonRecomp`; настройки и сохранения — в `<корень>/.config/MarathonRecomp`. Домашней папки у приложения на Android нет.
- **`logger_android`** — logcat и `log.txt` рядом с папкой игры (прошлый запуск сохраняется как `log_prev.txt`), stderr перенаправлен в лог (ошибки Plume и Vulkan), в начале — устройство, SoC и ядро. При фатальном сигнале дописывается короткий отчёт (сигнал, адрес, PC/LR в виде библиотека+смещение), затем работает обычный системный tombstone. Каждый долгоживущий поток получает свой альтернативный стек сигналов, поэтому сообщается и переполнение стека. У тестировщиков часто нет `adb`, файл копируется по USB/MTP.
- **Служебный лог выключен** (`os/logger.h`) — игра пишет каждый запрос файла дважды и каждый вызов заглушки. На Android каждая строка стоила записи в logcat и в файл, тысячи строк на каждый переход между сценами. Теперь такие строки пропускаются до форматирования; файл `log_utility.enabled` возвращает их для отладки.
- **`process`, `version`, `user`, `media`, `thread`** — реализации небольших интерфейсов ОС для Android.

## 3. Рендер (`MarathonRecomp/gpu/video.cpp`, `thirdparty/plume`)

- **Буфер RGBA** — swapchain на Android даёт только форматы RGBA, а на ПК по умолчанию BGRA.
- **Жизненный цикл поверхности** — при уходе в фон Android заменяет `ANativeWindow`. Swapchain каждый кадр сравнивает окно и пересоздаёт поверхность Vulkan (`VulkanSwapChain::recreateSurface`); ожидание кадра ограничено 2 секундами вместо бесконечного ожидания на мёртвом окне.
- **Голос за частоту кадров** — `ANativeWindow_setFrameRate` с настройкой FPS, чтобы экраны с высокой частотой не держали игру на частоте по умолчанию.
- **Pre-rotation swapchain** — у телефонов экран физически портретный. Со swapchain без поворота SurfaceFlinger поворачивал каждый альбомный кадр через композицию на GPU — на том же GPU, что и игра. Теперь swapchain создаётся с `preTransform = currentTransform`, а финальный гамма-проход сразу пишет повёрнутое изображение (`gamma_correction_ps.hlsl`). Экран выводит его напрямую. Файл `prerotation.disabled` возвращает старый путь.
- **Масштаб разрешения** — уменьшаются или увеличиваются только буферы сцены, а back buffer и HUD остаются в полном размере экрана: сцену растягивает собственный проход игры «Rasterize». В оригинале масштабировалось всё, и на телефонах картинка обрезалась или увеличивался HUD. Проверено при 60 % и 125 %.
- **Только альбомная ориентация** — SDL заменял `sensorLandscape` из манифеста на «любую ориентацию» для окна с изменяемым размером; `SDL_HINT_ORIENTATIONS = "LandscapeLeft LandscapeRight"` это исправляет.
- **GPU без текстур BC (Mali, PowerVR; v0.1.5, перенесено из UnleashedRecomp-Android 1.5.0)** — текстуры игры сжаты в BC (DXT), а стоковые драйверы Mali/PowerVR их не читают. Если устройство не поддерживает BC, `LoadTexture` при загрузке распаковывает блоки через [bcdec](https://github.com/iOrange/bcdec) и перекодирует в ETC2/EAC через [etcpak](https://github.com/wolfpld/etcpak) (тот же объём памяти, кроме прозрачных BC1); без ETC2 текстуры распаковываются в RGBA. BC-текстуры, которые игра создаёт сама, создаются как RGBA8. Наборы дескрипторов текстур и сэмплеров ограничиваются лимитами устройства. `bc_fallback.enabled` включает этот путь на Adreno для проверки (со словом `decode` внутри — RGBA вместо ETC2). **На устройстве с Mali ещё не проверено.**
- **Путь Vulkan 1.2 в Plume (v0.1.5)** — на драйверах 1.2+ descriptor indexing, scalar block layout, buffer device address и mirror clamp включаются через `VkPhysicalDeviceVulkan12Features`: драйверы вроде стокового Mali не обязаны перечислять старые имена расширений. `MIRROR_ONCE` заменяется на `MIRRORED_REPEAT`, если не поддерживается, функции устройства загружаются через `volkLoadDevice`, а GPU без scalar block layout или buffer device address теперь завершает запуск с понятным сообщением в `log.txt`. Turnip (Adreno) тоже идёт этим путём; проверено на Adreno 725.
- **Исправления для Mali (v0.1.6, найдены с тестировщиками на Mali-G57 MC2 и G710)** — (1) в раскладке конвейеров Марафона 5 наборов дескрипторов (3 вида набора текстур, сэмплеры, буфер conditional survey в `space4`); драйверы с `maxBoundDescriptorSets = 4` падают или отвергают конвейеры, использующие set 4. При меньше чем 5 наборах буфер становится binding 0 набора сэмплеров (сэмплеры — binding 1), а SPIR-V всех шейдеров перепривязывается при загрузке (`RemapSpirvForCompactDescriptorSets`). (2) Все вершинные шейдеры пишут `SV_ClipDistance` (пользовательские плоскости отсечения Xbox); без `shaderClipDistance` этот выход превращается в обычный неиспользуемый, а capability убирается (`StripSpirvClipDistance`), поэтому плоскости отсечения выключены. (3) Выборки Xenos «3D» перекомпилированы как `Texture2DArray`, а игра кладёт туда обычные 2D-текстуры; теперь у каждой 2D-текстуры есть второй вид «массив 2D» для этой ячейки (Vulkan требует совпадения типов; Turnip прощал несовпадение). (4) Запасной механизм (сейчас не срабатывает): если GPU сообщает меньше 20 вершинных атрибутов, номера входов (у Марафона 0–19) уплотняются. Перепривязки SPIR-V проверены офлайн через `spirv-val` на всех шейдерах игры.
- **Диагностика (v0.1.6)** — в `log.txt` пишутся GPU, драйвер, версия Vulkan, лимиты (`GPU limits:`) и возможности, шаги инициализации (`Init: …`), каждый отвергнутый драйвером конвейер (шейдеры, форматы, входы) и строки logcat приложения после первой ошибки. Отвергнутые конвейеры не биндятся (их отрисовка пропускается, а не роняет драйвер). В отчёте о сбое — имя потока, стек вызовов по frame pointers и конвейер, компилировавшийся в этот момент.

## 4. Драйверы Vulkan (`os/android/vulkan_driver_android.cpp`, `android/turnip-drivers`)

- Четыре встроенные сборки Mesa Turnip (см. `android/turnip-drivers/README.md`). **«Авто»** выбирает по устройству: Snapdragon 8 Elite (SM8750, Adreno 830) → сборка Mesa 26.3 с исправлением gralloc UBWC; другие Adreno → встроенная сборка по умолчанию; GPU не от Adreno → системный драйвер; ранее импортированный драйвер остаётся выбранным.
- Можно импортировать свой драйвер (`.so` или `.zip` AdrenoTools/ExynosTools) из лаунчера или положив его в `driver_import/`.
- **Восстановление после сбоя** — перед загрузкой стороннего драйвера пишется маркер, который удаляется только когда устройство Vulkan и рабочий swapchain созданы. Если игра упала в промежутке, следующий запуск использует системный драйвер.
- Встроенные драйверы копируются во внутреннюю память один раз на каждую установку APK (штамп с путём библиотек APK и размерами), а не сравниваются побайтно при каждом запуске.
- Перенесено из UnleashedRecomp-Android 0.6.1 и переведено на SDL3.

## 5. Производительность

Замеры на POCO F5 (SM7475) в HUB, с `perf_capture.enabled` и трассами Perfetto:

- **Рабочие потоки и малые ядра.** Главный поток ждал около 6,4 мс за кадр рабочие потоки игры FrustumCulling, UpdateResource и FrameSynchronizer, которые планировщик держал на малых ядрах Cortex-A510 на ~1,1 ГГц. Закрепление их за большими ядрами (`os/android/thread_hints_android.cpp`) подняло HUB с **46–50 до 60 FPS** без системного буста: нагрузка на большом кластере подняла и его частоту, и главный поток стал работать на ~2,46 ГГц вместо ~1,5 ГГц.
  - Решение принимается по `cpu_capacity`: ядро малое, если оно слабее половины самого сильного; закрепление включается, только если малые ядра есть и остальных ядер не меньше трёх. На Snapdragon 8 Elite (малых ядер нет) оно выключено. После возврата из фона маска применяется заново. `thread_affinity.disabled` выключает, `cpus=` в `thread_affinity.enabled` задаёт набор вручную.
  - Сначала пробовали uclamp для отдельных потоков; на проверенной прошивке приложению это запрещено (EPERM). Механизм остался опциональным (`thread_uclamp.enabled`).
- **Группа 1 XenonRecomp** (CTR, XER, CR и резервирование как локальные переменные): машинный код −13,5 % (41,97 → 36,29 МБ `.text`). Отдельного прироста FPS тогда измерить не удалось (то состояние упиралось в GPU), но работа CPU на кадр уменьшается. Причину, по которой оригинал держит опции выключенными, проверили: это значения по умолчанию для начальной отладки; mid-asm хуки и новые инструкции форка совместимы с локальными регистрами.
- **Pre-rotation** — убирает композицию SurfaceFlinger на GPU (раздел 3).
- **Оставшиеся ограничения на POCO F5:** в HUB GPU тратит ~15,5 мс из 16,7 при масштабе 60 %, загрузки сцен дают короткие просадки.

### Pixel 7 Pro (Tensor G2, Mali-G710), v0.2.0

Замеры по `log.txt` тестировщиков (`[perf]`, профайлер CPU, `[waits]`/`[wakers]`, `[gpu-passes]`). v0.1.6 давала на уровнях 24–31 FPS при масштабе 25 %, тестовые сборки v0.2.0 — 45–55 FPS (41–57 FPS при 50 %).

- **Главный поток и поток рендера на малых ядрах.** Поток, который спит в ограничителе кадров, кажется планировщику Tensor лёгким, поэтому главный игровой поток и поток рендера оставались на ядрах Cortex-A55 на 0,9–1,2 ГГц, пока большие ядра простаивали. Теперь они закрепляются вместе с рабочими потоками (`main_render=1` в `thread_affinity.enabled` — по умолчанию; `=0` возвращает прежнее поведение).
- **Кого ждёт главный поток.** Перехват `WaitForSingleObject` игры (`sub_82537DC0`) запоминает место вызова в гостевом коде, а `Event::Set`/`Semaphore::Release` — какой поток выставил объект, которого ждёт главный. Почти всё ожидание приходилось на одно место вызова, а будили его рабочие потоки ModelStandard, частиц, Havok и документа, которых не было в списке закрепления; они добавлены. Закрепление проверяется раз в 2 секунды и восстанавливается (маска считается потерянной, только если в ней есть ядра вне набора потока, поэтому ядра, усыплённые ядром ОС, не дают срабатываний).
- **Переключения FPCR.** Профайлер показал `sub_82168C48` — ~18 % времени игрового потока: перекомпилированные векторные скалярные произведения (`vmsum3fp128`/`vmsum4fp128`) ставят округление «к нулю» перед каждой инструкцией и возвращают его после, только в этой функции 33 записи `msr fpcr`. Опция XenonRecomp `merge_rounding_overrides` (патч `android/patches/xenonrecomp`, CMake `MARATHON_RECOMP_PPC_MERGE_ROUNDING`) оставляет режим на следующие скалярные произведения и инструкции, не зависящие от округления (векторные загрузки/сохранения, слияния, перестановки, splat, целочисленные пересылки, загрузки и сохранения), и восстанавливает его перед любой другой инструкцией, на метках, mid-asm хуках и в конце функции. С выключенной опцией сгенерированный код совпадает с прежним (150 из 150 файлов); с включённой проверка не нашла ни одной инструкции, которая выполнялась бы с другим режимом округления, а функция выше сократилась с 372 до 251 инструкции (33 → 3 записи FPCR). Вместе с закреплением время CPU игрового потока на кадр сократилось примерно вдвое.
- **GPU.** На уровнях ~48 проходов рендера за кадр. Около 10 из 12–17 мс не зависят от масштаба рендера: карты теней 512×512 (8 проходов), ~25 проходов bloom/яркости по одной отрисовке и четыре прохода в разрешении экрана (HUD и итоговая картинка, затем гамма с поворотом экрана). На тайловых GPU каждый проход загружает и сохраняет свои вложения, поэтому в Plume сделаны два изменения (переключатель `render_pass_optimizations.disabled` выключает оба): полная очистка до первой отрисовки становится `LOAD_OP_CLEAR` совместимого render pass вместо `vkCmdClearAttachments` после загрузки, а барьеры получают маски стадий и доступа по старому и новому layout текстуры вместо «всех команд» (чтение предполагается в вершинных и фрагментных шейдерах, потому что шейдеры Xenos могут читать текстуры в вершинной стадии; буферы, `GENERAL` и `PRESENT` сохраняют полные маски). Время GPU на уровнях снизилось примерно на 10–15 % (тени 3,0–5,2 → 2,3–4,4 мс, цепочка bloom 1,2–1,5 → 0,6–0,9 мс; сцены не совпадали). Разрезы одного прохода барьером на той же цели тоже измерены: ~5 на кадр, все — проходы с одной отрисовкой, поэтому объединять проходы через барьеры не стали.
- **Ожидание дисплея.** Кадр занимает 18–24 мс: ~10–12 мс работы игрового потока и ~5–6 мс ожидания следующего изображения цепочки показа. Драйвер даёт 5 изображений при любом запросе (POCO F5 — 4), поэтому тройная буферизация ничего не меняет.
- **ADPF.** Сессия подсказок производительности охватывает игровой поток, поток рендера и поток показа и получает время CPU и GPU одного и того же кадра. В наших логах PowerHAL Pixel через неё не поднимал `uclamp` потоков (читается через `sched_getattr`); выставить uclamp само приложение на этом ядре не может (EPERM). На POCO F5 ADPF нет.
- **Загрузки.** Перекодирование BC→ETC2 занимало ~15 % игрового потока при загрузке уровня. Результат зависит только от исходной текстуры и целевого формата, поэтому он хранится под хешем XXH3-128 в `<внутренняя память>/texture_cache` (с размером и хешем содержимого у каждой записи, до 1 ГБ) — около 1,5 с работы CPU меньше на каждую загрузку уровня.
- **Не сделано** (много работы, выигрыш не гарантирован): `DONT_CARE` для глубины, которая потом не читается, объединение проходов с одной отрисовкой (нужны изменения шейдеров), облегчённые тени, перенос гаммы в последний проход игры.

## 6. Управление

- **Сенсорное управление на экране** (`ui/touch_controls.*`, перенесено из UnleashedRecomp-Android) с редактором раскладки, который запускается из лаунчера, и периферия `HID::Touch`, подключаемая вместе с клавиатурой и мышью первого игрока. Касания не создают событий мыши (`SDL_HINT_TOUCH_MOUSE_EVENTS = 0`). В режиме «Авто» ввод с физического геймпада скрывает экранные кнопки.
- Пока не адаптировано: D-pad в меню и одна кнопка «Пропустить» в роликах (заготовки есть, вызовы для Sonic 2006 не подключены).

## 7. Лаунчер и приложение Android (`android-apk/`)

- **`MarathonLauncherActivity`** — состояние игры (готова, число DLC), установка из ZIP или папки через Storage Access Framework, выбор и перенос хранилища, драйвер Vulkan и режим рендера, настройки сенсорного управления, пропуск заставок, логи, окно **«Инфо»**. В разделе **«Дополнительно» → «Отладка»** — переключатели игры из раздела 8; у каждого есть рекомендуемое положение, отличающиеся подсвечиваются и перечисляются, кнопка **«Рекомендуемые настройки»** их возвращает. Переключатели записываются файлами-маркерами при запуске игры, а игра пишет найденные маркеры в строку `[switches]` в `log.txt`. Оформление рисуется кодом (`LauncherStyle.java`) в стиле меню 2006 года. Строки: английский (по умолчанию) и русский.
- **`MarathonActivity`** — SDL activity, которая запускает `libmain.so`.
- **`MarathonDocumentsProvider`** — открывает папку игры, сохранения и папку обмена в системном приложении «Файлы» (Android 11+ скрывает `Android/data` от файловых менеджеров).
- Отдельный идентификатор приложения `io.github.sansnope.marathonrecomp.android`, ставится рядом с другими портами.

## 8. Переключатели (файлы в папке игры)

| Файл | Действие |
|---|---|
| `overlay.enabled` | оверлей производительности (в лаунчере — «Монитор производительности») |
| `perf_capture.enabled` | строка `[perf]` раз в 2 секунды и сводки `[waits]`, `[wakers]`, `[gpu-passes]`, `[gpu-frame]`, `[texture-cache]` (в лаунчере — «Лог производительности»). v0.1.6 создавала его автоматически; с v0.2.0 лаунчер удаляет такой автоматический файл |
| `perf_sampling.enabled` | профайлер CPU игрового потока: `[prof]`, `[threads]`, `[cpufreq]` раз в 20 секунд (в лаунчере — «Профайлер CPU») |
| `pipeline_cache.disabled` | без кэша конвейеров Vulkan на диске (`cache/pipeline_cache.bin`) |
| `thread_affinity.disabled` | без закрепления потоков (в лаунчере — «Игровые потоки на быстрых ядрах») |
| `thread_affinity.enabled` | переопределения `cpus=4-7`, `workers=…`, `main_render=0` |
| `thread_affinity_main_strongest.enabled` | эксперимент: главный игровой поток только на ядрах с наибольшей производительностью (нужно не меньше двух) |
| `performance_hint.disabled` | без сессии подсказок производительности ADPF |
| `render_pass_optimizations.disabled` | проходы рендера Vulkan как до v0.2.0 (без очистки при открытии, полные маски барьеров) |
| `texture_cache.disabled` | без кэша перекодированных BC→ETC2 текстур |
| `triple_buffering.enabled` | эксперимент: запрашивать 3 изображения цепочки показа (драйверы обычно и так дают больше) |
| `precise_frame_limiter.enabled` | эксперимент: ограничитель кадров спит до 0,5 мс до срока вместо 2 мс |
| `log_utility.enabled` | служебные строки лога (загрузки файлов, заглушки) |
| `prerotation.disabled` | swapchain без pre-rotation |
| `thread_uclamp.enabled` | uclamp для потоков (прошивки часто запрещают) |
| `bc_fallback.enabled` | проверка перекодирования BC→ETC2 на GPU с поддержкой BC (`decode` внутри — BC→RGBA) |
| `descriptor_sets_compact.enabled` | включить раскладку из 4 наборов (обход для Mali) на других GPU |
| `clip_distance_strip.enabled` | включить удаление `ClipDistance` (обход для Mali) на других GPU |
| `vertex_locations_compact.enabled` | включить уплотнение номеров вершинных входов на других GPU |

Папка игры — `Android/data/io.github.sansnope.marathonrecomp.android/files/MarathonRecomp`, если в лаунчере не выбрано другое хранилище.
